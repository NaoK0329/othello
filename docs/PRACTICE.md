# 練習用の課題（Issue のネタ）

GitHub に上げたら、これらを1つずつ Issue として登録し、メンバーで分担してみてください。
★ が少ないものから始めるのがおすすめです。

## 単独で取り組める課題（コンフリクトしにくい）

| 難易度 | 内容 | 主に触るファイル |
|---|---|---|
| ★ | 終局時に「何石差で勝ったか」を表示する | `cli.py` |
| ★ | 石の記号を変えられるオプション `--ascii`（`X` / `O` / `.`） | `cli.py` |
| ★★ | 一番多く裏返せる場所を選ぶ `GreedyAI` を追加 | `players.py` |
| ★★ | 角を優先する `CornerAI` を追加 | `players.py` |
| ★★ | 黒/白どちらを AI にするか選べるようにする（`--ai-black`） | `cli.py` |
| ★★★ | 「待った（1手戻す）」機能 | `board.py`, `cli.py` |
| ★★★ | 対局の棋譜をファイルに保存・読み込み | 新規ファイル |

## わざとコンフリクトを体験する課題

2人で同時に、次の2つを **別ブランチで** 進めてからマージしてみてください。
どちらも `cli.py` の `render()` を変更するので、必ずコンフリクトします。

- Aさん: 盤面の上に「○手目」を表示する
- Bさん: 盤面の左右に枠線を付ける

後からマージする人が、CONTRIBUTING.md の「コンフリクトが起きたら」の手順で解決します。

## 練習の進め方の例（3人チーム）

1. 1人が GitHub にリポジトリを作って push し、他の2人を Collaborator に招待
2. Settings → Branches で main にブランチ保護（PR 必須・承認1件）を設定
3. 各自 `git clone` して、上の課題から1つずつ Issue を担当
4. ブランチ → コミット → PR → お互いにレビュー → マージ
5. マージされたら他の人は `git switch main && git pull` で最新を取り込む
